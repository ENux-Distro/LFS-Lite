Chapter 1. Preparing the Environment

Before a single line of source code is compiled, a clean and consistent build environment must be established. This chapter creates the directory hierarchy, sets the environment variables that all subsequent chapters rely upon, verifies the source tarballs, and writes the static configuration files that will live in the final root filesystem.

Approximate time: < 5 minutes
Disk space used: Negligible

1.1. Setting Up the Build Directory

All work in this book takes place under a single root directory anchored at /mnt/lfs-lite. Establish the core environment variables now and add them to your shell's startup file so they persist across terminal sessions: 

export LFS=/mnt/lfs-lite
export LFS_SOURCES=$LFS/sources
export LFS_ROOT=$LFS/rootfs
export LFS_TOOLS=$LFS/tools
export JOBS=$(nproc)

cat >> ~/.bashrc << "EOF"
export LFS=/mnt/lfs-lite
export LFS_SOURCES=$LFS/sources
export LFS_ROOT=$LFS/rootfs
export LFS_TOOLS=$LFS/tools
export JOBS=$(nproc)
EOF

source ~/.bashrc

1.2. Creating the Directory Skeleton

Create the directory structure that will house both the build artifacts and the final root filesystem: 

mkdir -pv $LFS/{sources,rootfs,tools,build,logs}

mkdir -pv $LFS_ROOT/{boot,dev,etc,home,lib64,proc,root,run,sys,tmp}
mkdir -pv $LFS_ROOT/usr/{bin,lib,sbin,share,include}
mkdir -pv $LFS_ROOT/var/{log,run,tmp}

chmod 1777 $LFS_ROOT/tmp
chmod 1777 $LFS_ROOT/var/tmp

1.3. Verifying Source Tarballs

The following sources must be present in $LFS_SOURCES: 

ls -lh $LFS_SOURCES/

Expected files: 

bash-5.3.tar.gz
coreutils-9.11.tar.xz
grub-2.14.tar.xz
linux-7.1.2.tar.xz
musl-1.2.6.tar.gz
util-linux-2.42.tar.xz
busybox/          (git clone)

BusyBox must be cloned from its official repository if not already present: 

if [ ! -d $LFS_SOURCES/busybox ]; then
    cd $LFS_SOURCES
    git clone https://git.busybox.net/busybox
fi

ls $LFS_SOURCES/busybox/Makefile

1.4. Establishing a Build Log

Pipe all build output through tee so that failures can be diagnosed after the fact: 

export LFS_LOG=$LFS/logs/build-$(date +%Y%m%d-%H%M).log

For each build step in subsequent chapters you may optionally wrap commands as follows: 

make 2>&1 | tee -a $LFS_LOG

1.5. Creating Essential Symlinks

The final root filesystem must contain symbolic links to satisfy tools that hard-code paths based on traditional Unix conventions. Modern systems merge /bin, /lib, and /sbin into their /usr counterparts: 

ln -sv usr/bin  $LFS_ROOT/bin
ln -sv usr/lib  $LFS_ROOT/lib
ln -sv usr/sbin $LFS_ROOT/sbin

Verify the symlinks are correct:

ls -la $LFS_ROOT/bin $LFS_ROOT/lib $LFS_ROOT/sbin

Each must show a symlink arrow, for example bin -> usr/bin. If any shows as a directory, the symlink was not created — remove it with rm -rf $LFS_ROOT/bin and re-run the ln command.

Note

bin, lib, and sbin must not exist as directories before these commands run. This is why they were deliberately omitted from the mkdir in Section 1.2. If you pass ln a target that already exists as a directory, it places the symlink inside it rather than replacing it.

1.6. Creating Static Configuration Files

Several configuration files must exist in the final system before it can boot. Create them now so that they are in place throughout the build: 

echo "lfslite" > $LFS_ROOT/etc/hostname

cat > $LFS_ROOT/etc/passwd << "EOF"
root:x:0:0:root:/root:/bin/bash
EOF

cat > $LFS_ROOT/etc/group << "EOF"
root:x:0:
EOF

cat > $LFS_ROOT/etc/hosts << "EOF"
127.0.0.1   localhost
127.0.1.1   lfslite
::1         localhost
EOF

cat > $LFS_ROOT/etc/profile << "EOF"
export PATH=/usr/bin:/usr/sbin:/bin:/sbin
export PS1='[\u@\h \W]\$ '
export HOME=/root
EOF

1.7. Setting Build Flags

Set the following environment variables in your current shell before beginning Chapter 2. They control compiler behaviour for all subsequent package builds: 

export CC=gcc
export CXX=g++
export CFLAGS="-O2 -pipe"
export CXXFLAGS="-O2 -pipe"
export MAKEFLAGS="-j${JOBS}"

The meaning of these flags:

-O2

Enable a significant set of compiler optimisations without the occasional correctness issues that -O3 can introduce in sensitive low-level code.

-pipe

Instruct GCC to use pipes rather than temporary files for inter-stage communication, improving build speed on most systems.

-j${JOBS}

Parallelise the build across all available CPU cores. Set by export JOBS=$(nproc) above.

With the environment in place, you are ready to build the first package. Proceed to Chapter 2: Building musl libc.
