Troubleshooting

This chapter documents the most common failures encountered when building and booting LFS-Lite, their root causes, and how to resolve them. Failures are organised by the stage at which they manifest.

Build-Time Failures

Undefined reference to ... during compilation

Symptom: Linker errors such as undefined reference to `__errno_location' or undefined reference to `malloc' appear during make.

Causes and resolutions:

  • The musl-gcc wrapper is not being used. Verify CC="$LFS_TOOLS/musl-gcc" is present in the configure invocation and that the wrapper file exists and is executable: 
    ls -la $LFS_TOOLS/musl-gcc
$LFS_TOOLS/musl-gcc --version
  • musl headers are not at the expected path. Verify: 
    ls $LFS_ROOT/usr/include/stdio.h
  • The static library is missing. Verify: 
    ls $LFS_ROOT/usr/lib/libc.a

configure: error: C compiler cannot create executables

Symptom: The ./configure step fails immediately with a compiler test failure.

Causes and resolutions:

  • The musl-gcc wrapper has a syntax error or incorrect path. Test it directly: 
    $LFS_TOOLS/musl-gcc /tmp/musl-test.c -o /tmp/test-out 2>&1
  • The $LFS_ROOT variable is not exported. Verify: 
    echo $LFS_ROOT
    It must print /mnt/lfs-lite/rootfs. If empty, re-source ~/.bashrc.

Parallel build fails but -j1 succeeds

Symptom: make -j$(nproc) fails with an error, but make -j1 completes successfully.

This is a Makefile parallelism bug in the package — not an environment problem. Use -j1 for the affected package and report the issue upstream. Known packages with occasional parallel build issues: bash, GRUB.

Boot-Time Failures

Kernel panic: VFS: Unable to mount root fs

Symptom: The kernel boots, the initramfs may or may not start, but the system panics with: 

Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0)

On a live ISO, this panic means the kernel extracted the initramfs but the initramfs /sbin/init script failed before or during switch_root. There is no root= UUID to check — the live ISO grub.cfg does not pass one.

Causes and resolutions:

  • initramfs /sbin/init failed silently: Add set -x at the top of the initramfs /sbin/init script, rebuild the initramfs (Chapter 9), and reboot. Shell trace output will show exactly which command failed.
  • The live root was not found: The initramfs init script must mount the live medium (e.g. /dev/sr0 for a CD-ROM, or a squashfs loop mount) before calling switch_root. Verify that the mount succeeds inside the initramfs by dropping to a shell: replace the exec switch_root line temporarily with exec sh and inspect /mnt/root.
  • ext4 not in kernel: Verify CONFIG_EXT4_FS=y was set before kernel compilation. Recompile if necessary.
  • ISO 9660 driver missing: When booting from optical media, CONFIG_ISO9660_FS=y (or built as a module) must be present. Verify with: 
    grep ISO9660 $LFS_SOURCES/linux-7.1.2/.config
  • Optical or virtio driver missing: For QEMU with -cdrom, CONFIG_BLK_DEV_SR=y and CONFIG_ATA_PIIX=y are required. For -drive if=virtio, CONFIG_VIRTIO_BLK=y. Recompile the kernel with the correct options.

switch_root: failed to execute /sbin/init

Symptom: The initramfs runs successfully and mounts the root partition, but switch_root fails to execute /sbin/init.

Causes and resolutions:

  • /sbin/init does not exist on the real root. Verify: 
    ls -la $LFS_ROOT/sbin/init
  • /sbin/init is not executable: 
    chmod +x $LFS_ROOT/sbin/init
  • The shebang #!/bin/bash references /bin/bash, but bash is at /usr/bin/bash and /bin is not yet a symlink. Verify the symlink from Section 1.5: 
    ls -la $LFS_ROOT/bin
    It must be a symlink pointing to usr/bin.

Blank or garbled screen after GRUB

Symptom: GRUB loads and the kernel entry is selected, but the screen goes blank with no further output.

Causes and resolutions:

  • Add console=ttyS0 to the kernel command line in grub.cfg and connect a serial terminal. This bypasses video mode issues entirely.
  • Add nomodeset to the kernel command line to disable Kernel Mode Setting and use the BIOS text mode framebuffer.
  • In QEMU, use -nographic and console=ttyS0 together for serial-only output.

GRUB: file not found

Symptom: GRUB reports that vmlinuz-7.1.2 or initramfs.cpio.gz cannot be found.

Causes and resolutions:

  • Path prefix error: When /boot is a separate partition, GRUB's root is that partition. Files must be referenced as /vmlinuz-7.1.2, not /boot/vmlinuz-7.1.2. The installer-generated grub.cfg handles this correctly via the search --fs-uuid directive.
  • UUID mismatch: Run blkid from a live system to confirm the boot partition UUID matches the one in grub.cfg.

Runtime Failures

error while loading shared libraries: libc.so

Symptom: After booting into the final system, running a command produces: error while loading shared libraries: libc.so: cannot open shared object file.

Causes and resolutions:

  • The musl shared library is absent or at the wrong path. Verify from the chroot: 
    ls -la /usr/lib/libc.so
ls -la /lib64/ld-musl-x86_64.so.1
  • util-linux was built as dynamically linked but the dynamic linker path embedded in the binary does not match the installed location. Check with: 
    readelf -l /usr/sbin/fdisk | grep interpreter
    The interpreter path must match the actual location of ld-musl-x86_64.so.1.

BusyBox switch_root not found in initramfs

Symptom: The initramfs /init script fails because switch_root is not found.

Verify CONFIG_SWITCH_ROOT=y in the BusyBox config and that the symlink was created: 

grep 'CONFIG_SWITCH_ROOT' $LFS_SOURCES/busybox/.config
ls -la $LFS/initramfs/bin/switch_root

If switch_root is not in the config, enable it, rebuild BusyBox (Chapter 6), and repackage the initramfs (Chapter 9).

musl-test binary segfaults

Symptom: The musl verification binary in Section 2.7 segfaults immediately.

Causes and resolutions:

  • The dynamic linker is not at the path embedded in the binary. The wrapper passes an absolute build-time path. Ensure $LFS_ROOT/lib64/ld-musl-x86_64.so.1 exists and is not a broken symlink.
  • Architecture mismatch: verify the host is x86_64 with uname -m. On a 32-bit host a different musl dynamic linker name is required.
