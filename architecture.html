System Architecture Overview

The Two-Stage Boot Model

LFS-Lite uses a two-stage boot architecture, which is standard in modern Linux systems. Understanding this model before touching any source code is essential — it explains why certain packages exist, why the build order matters, and where each component lives in the final system. 

BIOS/UEFI
    │
    ▼
GRUB Bootloader
    │
    ▼
Linux Kernel (vmlinuz)
    │
    ▼
initramfs  (BusyBox environment, in RAM)
    │  ┌─ mount /proc /sys /dev
    │  ├─ locate real root device
    │  └─ run switch_root
    │
    ▼
Final Root Filesystem
    │  ┌─ musl libc
    │  ├─ bash
    │  ├─ coreutils
    │  ├─ util-linux
    │  └─ custom PID 1 init
    │
    ▼
Login shell / userspace

This architecture exists for sound engineering reasons. The kernel, once loaded, needs a minimal environment to perform device detection, mount the real root filesystem, and then hand control to the main system. The initramfs provides this environment without requiring the final root filesystem to contain all required early-boot tooling.

Directory Layout of the Target System

The final root filesystem follows a simplified version of the Filesystem Hierarchy Standard (FHS). The layout is intentionally lean: no /opt, no /srv, no subsystem directories that serve no purpose in a minimal system. 

/
├── bin/       → usr/bin  (symlink, FHS merge)
├── boot/      Kernel image, initramfs, GRUB config
├── dev/       Device files (populated by kernel devtmpfs)
├── etc/       fstab, hostname, passwd, profile
├── home/      User home directories
├── lib/       → usr/lib  (symlink)
├── lib64/     Dynamic linker: ld-musl-x86_64.so.1
├── proc/      Kernel process information (procfs)
├── root/      Root user home directory
├── sbin/      → usr/sbin (symlink) + /sbin/init
├── sys/       Kernel device model (sysfs)
├── tmp/       Temporary files (tmpfs at runtime)
├── usr/
│   ├── bin/   bash, ls, cp, mount, dmesg, …
│   ├── lib/   libc.so, libc.a (musl)
│   ├── sbin/  fdisk, mkfs, agetty, …
│   └── share/ Locale data, man pages (minimal)
└── var/
    ├── log/   System logs
    └── run/   Runtime PID files

The Role of musl

musl libc is the C standard library for LFS-Lite. It provides the fundamental interface between application code and the Linux kernel: memory allocation, file I/O, process management, signal handling, and the POSIX threading model.

musl's design philosophy differs from glibc in several important ways:

Size

musl is dramatically smaller. A complete musl shared library is typically under 1 MB, compared to several megabytes for glibc.

Static linking

musl is designed from the ground up to produce correct and small statically linked binaries. glibc's static linking has historically had edge cases involving NSS (Name Service Switch) and dynamic loading.

Correctness

musl prioritises strict POSIX and C standard conformance over compatibility with poorly written software that relies on glibc-specific extensions.

Auditability

The musl source code is compact enough to be read in full by a single engineer in a reasonable timeframe. glibc's source runs to millions of lines.

The trade-off is compatibility: software written for glibc-specific extensions may not compile or run correctly against musl. For LFS-Lite's package set, this is not a concern.

initramfs vs. Final Root

A common source of confusion for newcomers is the distinction between the initramfs and the final root filesystem. The table below summarises the differences:

PropertyinitramfsFinal Root
StorageRAM (extracted from cpio archive)Disk (ext4 partition)
LifespanSeconds — until switch_rootRuntime of the system
ShellBusyBox ashGNU bash
CoreutilsBusyBox appletsGNU coreutils
Init/sbin/init (BusyBox-based script)/sbin/init (bash script, PID 1)
PurposeMount real root, pivotRun the actual system

Build Directory Layout

All build activity takes place under /mnt/lfs-lite: 

/mnt/lfs-lite/
├── sources/         Source tarballs and git clones
│   ├── musl-1.2.6/
│   ├── coreutils-9.11/
│   ├── bash-5.3/
│   ├── util-linux-2.42/
│   ├── busybox/     (git clone)
│   ├── linux-7.1.2/
│   └── grub-2.14/
├── rootfs/          The final root filesystem (installed with DESTDIR)
├── initramfs/       initramfs staging directory (BusyBox + /init)
├── tools/           Build helper scripts (musl-gcc wrapper)
├── logs/            Build logs
└── install.sh       Installer script
