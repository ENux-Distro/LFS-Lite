Chapter 2. Building musl libc

musl (pronounced “muscle”) is a lightweight, fast, and correct implementation of the C standard library. It targets the Linux kernel and provides POSIX, C99, and C11 interfaces. Unlike glibc, musl does not include optional features that increase code size or introduce complexity without clear benefit.

musl is the foundation of LFS-Lite. Every other package in this book links against it. It must be built first.

Approximate build time: < 2 minutes
Required disk space: ~30 MB
Source tarball: musl-1.2.6.tar.gz

2.1. Introduction to musl

musl provides:

  • The C standard library headers (stdio.h, stdlib.h, string.h, etc.)
  • The shared library (libc.so) that programs link against at runtime.
  • The static library (libc.a) for statically linked binaries.
  • The dynamic linker (ld-musl-x86_64.so.1) that loads shared libraries at program startup.

2.2. Extracting the Source

cd $LFS_SOURCES
tar -xzf musl-1.2.6.tar.gz
cd musl-1.2.6

2.3. Configuring musl

musl uses its own configure script, simpler than Autoconf-generated scripts but following the same ./configure --prefix=... convention. We install musl into the final root filesystem using --prefix=/usr with DESTDIR to redirect the installation: 

./configure \
    --prefix=/usr \
    --syslibdir=/lib64 \
    --enable-shared \
    --enable-static

The meaning of the configure options:

--prefix=/usr

Tells musl that its files logically reside under /usr. This affects the paths embedded into the shared library and the dynamic linker.

--syslibdir=/lib64

Specifies where the dynamic linker (ld-musl-x86_64.so.1) will be installed. /lib64 is the conventional location expected by the Linux kernel's ELF interpreter mechanism.

--enable-shared

Build the shared library (libc.so). Required for dynamically linked programs.

--enable-static

Build the static library (libc.a). Required for statically linked programs, including BusyBox.

2.4. Compiling musl

make -j${JOBS}

The musl build is fast — typically under two minutes on modern hardware. If the build fails, the most likely cause is a host compiler too old to support C11. Verify with gcc --version.

2.5. Installing musl

make DESTDIR=$LFS_ROOT install

musl installs the following key files (paths relative to $LFS_ROOT):

PathPurpose
usr/include/C standard library headers
usr/lib/libc.soShared library symlink
usr/lib/libc.aStatic library
lib64/ld-musl-x86_64.so.1Dynamic linker

Verify the installation:

ls -la $LFS_ROOT/lib64/
ls -la $LFS_ROOT/usr/lib/libc*
ls $LFS_ROOT/usr/include/stdio.h

2.6. Creating the musl-gcc Wrapper

Create a wrapper script that subsequent build chapters will use to compile and link against our musl installation rather than the host's glibc: 

mkdir -pv $LFS_TOOLS

cat > $LFS_TOOLS/musl-gcc << EOF
#!/bin/bash
exec gcc \\
    --sysroot=$LFS_ROOT \\
    -isystem $LFS_ROOT/usr/include \\
    -L$LFS_ROOT/usr/lib \\
    -L$LFS_ROOT/lib64 \\
    -Wl,-dynamic-linker,/lib64/ld-musl-x86_64.so.1 \\
    "\$@"
EOF

chmod +x $LFS_TOOLS/musl-gcc

Note

The -Wl,-dynamic-linker path is /lib64/ld-musl-x86_64.so.1 — a target-system path, not a host path prefixed with $LFS_ROOT. This value is baked into the ELF interpreter field of every binary the wrapper compiles. Inside the chroot (and in the final live system), the dynamic linker lives at /lib64/ld-musl-x86_64.so.1, so this must reflect the path as seen by the running system, not the path as seen by the build host. Using $LFS_ROOT/lib64/... here would produce binaries that cannot execute inside the chroot.

2.7. Verifying musl

Write a minimal C program and compile it against musl to confirm the installation is correct: 

cat > /tmp/musl-test.c << "EOF"
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    printf("musl libc is working.\n");
    return EXIT_SUCCESS;
}
EOF

$LFS_TOOLS/musl-gcc /tmp/musl-test.c -o /tmp/musl-test
/tmp/musl-test

Expected output:

musl libc is working.

Verify that the binary links against our musl (not the host's libc): 

ldd /tmp/musl-test

The output should reference ld-musl-x86_64.so.1 from within $LFS_ROOT. If it references the host's /lib/x86_64-linux-gnu/libc.so.6, the wrapper script is not being invoked correctly.
