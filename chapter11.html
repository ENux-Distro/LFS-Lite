Chapter 11. Switching Root into the Final System

Before committing to a disk installation, this chapter verifies the completeness of the final root filesystem and validates it by chroot-testing from the host. This is the last checkpoint before the installer writes everything to disk.

Approximate time: < 10 minutes
Risk level: Low — read-only validation only

11.1. Understanding switch_root

The transition from the initramfs environment to the final root filesystem is performed by the switch_root utility (provided by BusyBox in the initramfs). This operation:

  1. Moves all virtual filesystem mounts from the initramfs paths to the new root's paths.
  2. Deletes all files in the initramfs to free the RAM they occupied — the initramfs lives in memory, and freeing it matters on constrained systems.
  3. Performs a chroot into the new root.
  4. Executes the specified binary — our /sbin/init — as PID 1.

This is subtly different from a plain chroot. After switch_root completes, the initramfs filesystem is gone. The process tree is now rooted in the real filesystem. There is no going back.

11.2. Verifying the Final Root Filesystem

Run a final audit of the root filesystem before proceeding: 

# Check essential binaries
for binary in \
    $LFS_ROOT/usr/bin/bash \
    $LFS_ROOT/usr/bin/ls \
    $LFS_ROOT/usr/bin/cp \
    $LFS_ROOT/usr/bin/mount \
    $LFS_ROOT/usr/sbin/fdisk \
    $LFS_ROOT/sbin/init; do
    if [ -f "$binary" ]; then
        echo "OK:      $binary"
    else
        echo "MISSING: $binary"
    fi
done
# Check essential libraries
ls -la $LFS_ROOT/usr/lib/libc*
ls -la $LFS_ROOT/lib64/ld-musl-x86_64.so.1
# Check essential configuration files
for file in \
    $LFS_ROOT/etc/hostname \
    $LFS_ROOT/etc/fstab \
    $LFS_ROOT/etc/passwd \
    $LFS_ROOT/etc/profile \
    $LFS_ROOT/boot/vmlinuz-7.1.2 \
    $LFS_ROOT/boot/initramfs.cpio.gz \
    $LFS_ROOT/boot/grub/grub.cfg; do
    if [ -e "$file" ]; then
        echo "OK:      $file"
    else
        echo "MISSING: $file"
    fi
done

Every line must print OK:. If any file is missing, return to the relevant chapter and complete that step before continuing.

11.3. Chroot Testing

Enter the final root filesystem from the host using chroot to validate that the shell, coreutils, and util-linux are functional: 

sudo mount --bind /proc $LFS_ROOT/proc
sudo mount --bind /sys  $LFS_ROOT/sys
sudo mount --bind /dev  $LFS_ROOT/dev

sudo chroot $LFS_ROOT /usr/bin/bash --login

Inside the chroot, run these sanity checks: 

# Inside the chroot environment
echo "Running inside LFS-Lite chroot"
bash --version | head -1
ls --color=auto /usr/bin | head -10
mount --version
fdisk --version
dmesg --version
cat /etc/hostname
exit

After exiting the chroot, unmount the virtual filesystems: 

sudo umount $LFS_ROOT/dev
sudo umount $LFS_ROOT/sys
sudo umount $LFS_ROOT/proc

What a Successful Test Looks Like

If the chroot test passes — commands run, output is correct, no dynamic linker errors — the system is ready for disk installation. A dynamic linker error such as error while loading shared libraries: libc.so: cannot open shared object file indicates that util-linux was built as a shared-linked binary but the musl shared library is not at the expected path. Verify $LFS_ROOT/usr/lib/libc.so and $LFS_ROOT/lib64/ld-musl-x86_64.so.1 both exist.

11.4. Final Disk Space Summary

Before installing to a target disk, confirm the size of the completed root filesystem: 

du -sh $LFS_ROOT
du -sh $LFS_ROOT/usr/bin
du -sh $LFS_ROOT/usr/lib
du -sh $LFS_ROOT/boot

A minimal LFS-Lite root filesystem with statically linked coreutils and bash typically measures 80–150 MB. The kernel modules in /lib/modules/ may add another 50–200 MB depending on the build configuration.

Proceed to Chapter 12 to write the system to a target disk with the installer script.
