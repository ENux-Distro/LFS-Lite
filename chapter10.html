Chapter 10. Custom Init System

When the kernel finishes its own initialisation and pivots into the real root filesystem via switch_root, it executes /sbin/init. The process that takes this path becomes PID 1 — the ancestor of every other process on the system. This chapter designs and implements that process.

Approximate time: < 5 minutes
Files created: /sbin/init, /etc/fstab

10.1. The Role of PID 1

PID 1 occupies a singular position in the Unix process model. Its special properties are:

  • It is the direct or indirect ancestor of every other process.
  • When any process becomes an orphan (its parent has exited), it is re-parented to PID 1.
  • PID 1 is the only process to which the kernel will not deliver SIGKILL. If PID 1 ignores SIGKILL, the kernel will not force it to die.
  • If PID 1 terminates for any reason, the kernel panics immediately.

These properties mean that PID 1's design must be correct and resilient. LFS-Lite's init system is deliberately minimal — suitable for a single-user system or a learning environment. It does not implement service supervision, parallel startup, or dependency ordering. Those are the domain of full init systems such as systemd, runit, or s6.

10.2. Writing the Init Script

mkdir -pv $LFS_ROOT/sbin

cat > $LFS_ROOT/sbin/init << "EOF"
#!/bin/bash
#
# LFS-Lite /sbin/init — PID 1
# Minimal init for a single-user system.
#

PATH=/usr/bin:/usr/sbin:/bin:/sbin
export PATH

emergency_shell() {
    echo ""
    echo "--- EMERGENCY SHELL ---"
    echo "Type 'exit' to attempt to continue boot."
    /bin/bash --login
}

echo ""
echo "====================================="
echo "  LFS-Lite Init System"
echo "====================================="
echo ""

# Set hostname
if [ -r /etc/hostname ]; then
    hostname $(cat /etc/hostname)
    echo "Hostname: $(hostname)"
fi

# Mount virtual filesystems (may already be mounted if initramfs moved them)
if ! mountpoint -q /proc 2>/dev/null; then
    mount -t proc proc /proc || emergency_shell
fi

if ! mountpoint -q /sys 2>/dev/null; then
    mount -t sysfs sysfs /sys || emergency_shell
fi

if ! mountpoint -q /dev 2>/dev/null; then
    mount -t devtmpfs devtmpfs /dev || emergency_shell
fi

mkdir -p /dev/pts
mount -t devpts devpts /dev/pts -o gid=5,mode=620

mount -t tmpfs tmpfs /tmp -o mode=1777

# Mount remaining filesystems from /etc/fstab
if [ -r /etc/fstab ]; then
    mount -a -t nosysfs,noproc,nodevtmpfs,nodevpts 2>/dev/null
fi

# Bring up loopback network interface
if command -v ip >/dev/null 2>&1; then
    ip link set lo up
fi

echo ""
echo "Boot complete. Starting login shell."
echo ""

trap 'echo "SIGTERM — shutting down."; sync; poweroff -f' TERM
trap 'echo "SIGINT — rebooting.";    sync; reboot -f'    INT

# Restart shell on exit rather than panicking
while true; do
    /bin/bash --login -i </dev/console >/dev/console 2>&1
    echo "Shell exited — restarting in 1 second..."
    sleep 1
done
EOF

chmod +x $LFS_ROOT/sbin/init

Note on Design Decisions

The init script uses #!/bin/bash rather than #!/bin/sh. In an educational context, bash's more readable syntax and better error messages are preferred. The while true loop around the login shell ensures that if the user types exit, the system restarts a new shell rather than panicking. Signal handlers provide clean shutdown via poweroff and reboot.

10.3. Creating /etc/fstab

The filesystem table is read by mount -a in the init script. The rootfs fstab shipped inside the live ISO must not reference disk partitions such as /dev/sda2 — on a live ISO, the root is a tmpfs populated from the squashfs in memory, not a partition on any fixed disk. Disk partition entries belong in the fstab that the installer (Chapter 12) writes to the target system after installation. The live rootfs fstab only mounts virtual filesystems: 

cat > $LFS_ROOT/etc/fstab << "EOF"
# /etc/fstab — LFS-Lite (live)
# Disk partitions are NOT listed here. The installer writes
# a system-specific fstab with correct UUIDs after installation.
# <device>    <mountpoint>  <type>     <options>              <dump> <pass>
proc          /proc         proc       nosuid,noexec,nodev    0      0
sysfs         /sys          sysfs      nosuid,noexec,nodev    0      0
devtmpfs      /dev          devtmpfs   mode=0755,nosuid       0      0
devpts        /dev/pts      devpts     gid=5,mode=620         0      0
tmpfs         /tmp          tmpfs      mode=1777              0      0
EOF

10.4. Design Rationale

Several properties of this init system deserve explicit comment for the reader who intends to extend or replace it:

Zombie reaping

PID 1 must call wait() to reap zombie processes — processes that have terminated but whose exit status has not been collected. Bash's internal wait semantics perform this reaping implicitly for child processes of the shell, but a production init system would implement an explicit SIGCHLD handler.

No service management

A production init system forks background daemons and monitors them for unexpected termination. Adding this capability is left as an exercise. The runit or s6 init systems are excellent references for minimal but correct service supervision.

Single-user assumption

LFS-Lite's init provides one shell on /dev/console. A multi-user system would spawn one agetty per virtual terminal. util-linux provides agetty for this purpose.
