Final Boot Process Explanation

Understanding the boot process end-to-end consolidates the knowledge from all preceding chapters. Every component built in this book plays a specific, non-overlapping role in the sequence from power-on to interactive shell. This chapter traces that sequence in full.

Stage 1 — Firmware (BIOS/UEFI)

When the system is powered on, the firmware (BIOS or UEFI) initialises hardware: the CPU is brought to a known state, memory is tested and mapped, and PCIe buses are enumerated. The firmware then reads the first 512 bytes of the designated boot disk — the Master Boot Record (MBR). The MBR contains the first-stage GRUB bootloader code and the partition table. Control is transferred to the first-stage code.

Note

On UEFI systems the boot process differs: the firmware reads an EFI System Partition (ESP) and executes a .efi application directly. LFS-Lite's installer targets BIOS/MBR for simplicity. UEFI support would require grub-install --target=x86_64-efi and a FAT32 ESP partition.

Stage 2 — GRUB Stage 1 (MBR Code)

The GRUB first stage fits in 446 bytes (the MBR minus the partition table and boot signature). Its only capability is to locate and load GRUB's second stage, stored in the sectors between the MBR and the first partition — the “boot gap” or embedded GRUB core image.

Stage 3 — GRUB Stage 2 (/boot/grub/)

GRUB's second stage has a full ext2/ext4 filesystem driver and can read /boot/grub/grub.cfg. It:

  1. Displays the boot menu and waits for the configured timeout (5 seconds by default).
  2. Reads vmlinuz-7.1.2 from the boot partition into RAM.
  3. Reads initramfs.cpio.gz from the boot partition into RAM.
  4. Passes the kernel command line (root=UUID=... rw quiet) to the kernel.
  5. Jumps to the kernel's entry point.

The search --fs-uuid directive in grub.cfg allows GRUB to locate the boot partition by its UUID regardless of disk device ordering — a system with multiple disks will boot correctly even if the disk enumeration order changes between reboots.

Stage 4 — Kernel Initialisation

The kernel decompresses itself (the bzImage format contains a self-decompressing stub), then:

  1. Initialises the memory management subsystem and sets up virtual memory.
  2. Initialises the CPU (sets up GDT, IDT, paging).
  3. Scans and initialises hardware via the compiled-in drivers (CONFIG_ATA, CONFIG_VIRTIO_BLK, etc.).
  4. Sets up /dev via devtmpfs (CONFIG_DEVTMPFS_MOUNT).
  5. Extracts the initramfs cpio archive into a tmpfs and mounts it as the initial root.
  6. Executes /sbin/init from the initramfs as PID 1.

Stage 5 — initramfs /sbin/init (BusyBox)

The BusyBox-based /sbin/init script from Chapter 9 runs:

  1. Mounts /proc, /sys, /dev inside the initramfs.
  2. Reads /proc/cmdline to extract the root= parameter.
  3. Polls for the root block device to appear (up to 10 seconds, handling asynchronous driver initialisation).
  4. Mounts the real root partition at /mnt/root.
  5. Moves virtual filesystem mounts into /mnt/root so they are available after the pivot.
  6. Calls switch_root /mnt/root /sbin/init.

Stage 6 — switch_root

switch_root performs:

  1. Recursively deletes all files in the current (initramfs) root, freeing RAM.
  2. pivot_root into /mnt/root.
  3. chroot into the new root.
  4. exec the specified binary (/sbin/init) as PID 1.

After this call, the initramfs is gone. The kernel's root is now the ext4 partition on disk. PID 1 is now the bash-based init script from Chapter 10.

Stage 7 — LFS-Lite /sbin/init (bash)

The bash init script runs:

  1. Sets the hostname from /etc/hostname.
  2. Verifies and mounts /proc, /sys, /dev (already mounted by initramfs via mount --move).
  3. Mounts /dev/pts and /tmp.
  4. Runs mount -a to process /etc/fstab.
  5. Brings up the loopback network interface.
  6. Enters the shell restart loop — starts a bash login shell on /dev/console.

Stage 8 — Interactive Shell

Bash presents a prompt. The full userspace is available: ls, cp, mount, fdisk, dmesg, and all other tools built throughout this book.

The system is fully booted.

StageTypical Duration
Firmware POST1–3 seconds
GRUB (including timeout)5 seconds
Kernel initialisation0.5–2 seconds
initramfs< 1 second

Total~8–12 seconds
