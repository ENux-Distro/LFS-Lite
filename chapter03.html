Chapter 3. Building coreutils

GNU coreutils is the foundational userspace package on any GNU/Linux system. It provides the essential file, text, and shell utilities that every other piece of software assumes to be present: ls, cp, mv, rm, cat, echo, sort, wc, chmod, chown, mkdir, ln, and many others.

Without coreutils, a system is functionally unusable. It is built immediately after musl because it has no dependencies beyond the C standard library.

Approximate build time: 2–5 minutes
Required disk space: ~180 MB
Source tarball: coreutils-9.11.tar.xz

3.1. Introduction to GNU coreutils

coreutils 9.11 is a major release of the GNU coreutils package. Among the tools it provides are the implementations of ls, cp, mv, cat, sort, uniq, wc, head, tail, chmod, chown, ln, mkdir, rm, date, echo, printf, test, and many more. These are the primitives on which shell scripts and interactive sessions depend.

3.2. Extracting the Source

cd $LFS_SOURCES
tar -xJf coreutils-9.11.tar.xz
cd coreutils-9.11

3.3. Configuring coreutils

./configure \
    --prefix=/usr \
    --host=x86_64-linux-musl \
    --build=$(build-aux/config.guess) \
    --enable-no-install-program=kill,uptime \
    CC="$LFS_TOOLS/musl-gcc" \
    CFLAGS="-O2 -pipe" \
    LDFLAGS="-static"

The meaning of the configure options:

--prefix=/usr

Standard prefix for the final system.

--host=x86_64-linux-musl

Declares that the binaries will run on an x86_64 system using musl. This signals to the configure system that the C library is musl rather than glibc, enabling appropriate compatibility handling.

--build=$(build-aux/config.guess)

Auto-detects the build machine's triple. Must be stated explicitly when --host differs from the build machine.

--enable-no-install-program=kill,uptime

Excludes kill and uptime, which are provided by util-linux in forms better suited to the target system.

LDFLAGS="-static"

Links all coreutils binaries statically against musl. The resulting binaries have no shared library runtime dependencies and work correctly before the dynamic linker is available.

3.4. Compiling coreutils

make -j${JOBS}

coreutils is a large package. Expect this to take two to five minutes depending on hardware. The build is highly parallelisable and benefits significantly from multiple cores.

3.5. Running the Test Suite

coreutils includes a comprehensive test suite. Running it is strongly recommended: 

make check

Note

A small number of tests may fail due to host environment differences — for example, tests requiring root privileges for certain permission operations. These are benign. Failures in tests for core utilities such as cp, mv, or sort are not benign and must be investigated before proceeding.

3.6. Installing coreutils

make DESTDIR=$LFS_ROOT install

Verify that the key binaries are present and statically linked:

ls $LFS_ROOT/usr/bin/ls
ls $LFS_ROOT/usr/bin/cp
ls $LFS_ROOT/usr/bin/cat
file $LFS_ROOT/usr/bin/ls

The file command should report: 

…/usr/bin/ls: ELF 64-bit LSB executable, x86-64, statically linked, …

Note

Because $LFS_ROOT/bin is a symlink to usr/bin (created in Section 1.5), /bin/ls and /usr/bin/ls in the final system refer to the same file without any duplication.
